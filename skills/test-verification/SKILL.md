# 测试验证 + 完成门禁

<role>
适用于所有 opencode 项目的通用测试纪律，回答三件事：
1. 这个项目怎么测（探测测试栈，不假设框架）。
2. 每阶段的验证命令怎么定（对接 plan-review 复核清单 A 组）。
3. 什么算「真完成」（完成前测试门禁，杜绝「标记完成=没测试」）。
</role>

### 边界职责（避免与相邻技能职责重叠）

- `plan-review` 管「开工前计划复核」；本技能管「过程中怎么测 + 完成前验证」。
- `phased-refactor-and-report` 管「实现→测试→提交」流程纪律；本技能提供其中「测试」环节的具体依据。
- 项目级测试技能（如 `headless-page-smoke-test`）提供具体工具/脚本；本技能只定义流程，不重复项目细节。

## P1 探测测试栈（动手前）

1. 查 `package.json` scripts / 项目 AGENTS.md / `test/` 目录，确认真实测试入口（vitest/jest/pytest/自研 smoke 等），不假设。
2. 探测到 → 用真实命令与判定标准（退出码 / 明确断言）。
3. 探测不到 → 如实记录「该项目当前无自动化测试」，验证改走手动冒烟 + 人工核对，不猜命令、不伪造「测试通过」。

## P2 定每阶段验证命令（对接 plan-review A 组）

计划里每阶段必须落到可执行命令，至少覆盖该阶段改动影响的层：
- 纯逻辑改动 → 对应单测（如 `npm test` 或 `test/x.test.mjs`）。
- 前端页面 → 冒烟/渲染验证（有项目级 smoke 技能/脚本则引用）。
- 涉 lint/type → `npm run lint` / `npm run typecheck`。

命令要能判定成败（退出码/明确断言），不能是「我看一下」。

## P3 完成前测试门禁（Definition of Done）

1. 声明「任务完成」前，先跑受影响范围（P4）的测试，全部通过才算真完成；「标记完成但没跑测试」视为未完成，退回补测。
2. 受影响范围内的新增/改动代码：项目已建单测规范则须补对应测试；项目无单测规范时，至少跑该范围验证并如实说明验证方式。

## P4 受影响范围判定

- 用 `git diff` / `git status` 列出本次改动涉及的文件与模块，划定测试范围。
- 边界内改动 → 跑边界内测试；涉及共享/核心代码 → 跑全量相关测试。

## P5 测试失败循环

- 测试失败 → 先定位原因（跑失败用例、看错误信息），修复后重测；修复通过再继续。
- 不允许「带测试失败进入下一阶段」或「带测试失败标记完成」。

## 关键命令 / 模式

- 探测：`Get-Content package.json`（scripts）、`Get-ChildItem test`、查 AGENTS.md 测试规范。
- 划范围：`git diff --name-only`。
- 跑测试：项目声明的 test/lint/typecheck/smoke 命令。
- 写测试产物/脚本：遵循 `powershell-utf8-safety`（Write/Edit 或显式 UTF-8 API）。

## 红线兜底

- 先探测再定命令：探测不到测试入口时，如实改走手动冒烟 + 人工核对；不猜命令、不伪造「测试通过」。
- 完成前必须跑受影响范围测试：跑通才算真完成；「没跑测试」不算完成，退回补测。
- 测试失败先修复再继续：不得带病进入下一阶段或标记完成。
- 纯逻辑改动在项目已建单测规范时须补单测。
