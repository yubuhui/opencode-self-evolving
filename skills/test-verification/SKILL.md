# 轻量测试总控与完成门禁

<role>
从本次改动的直接路径、已知缺陷和项目必要门禁起步，用可重复核验的结果判断完成。方法库与界面专项放在 references，按具体风险读取；主观视觉与体验交人工验收。
</role>

## 一、范围与投入

1. 从项目 AGENTS、技能目录和真实测试配置定位已有用例、命令与必要门禁；已有准确记录优先复用。
2. 从需求、接口/契约和缺陷描述确定直接验收路径与独立预期；关键预期有歧义时确认。
3. 按影响选择投入：

| 风险 | 典型改动 | 投入 |
| --- | --- | --- |
| 低 | 可逆文案、注释、局部样式 | 针对性核对 + 已有检查 |
| 中 | 单个业务分支、输入规则、局部交互、缺陷修复 | 直接路径 + 已知复现 + 受影响约束 |
| 高 | 金额、删除、共享核心/写入、迁移 | 不变量、失败一致性、使用方与跨层回归 |

## 二、按风险选方法（references）

| 风险信号 | 读取 |
| --- | --- |
| 改动交互，或内容/布局/滚动/遮挡/焦点风险 | [界面与交互验证](references/ui-verification.md) |
| 边界、异常恢复、状态转换、并发/重复、解析、性能 | [测试场景设计](references/test-scenario-design.md) |
| 已实际启动应用或执行用户操作 | [运行时信号检查](references/runtime-diagnostics.md) |
| 需要记录用例与结论 | [验证记录](references/verification-record.md) |

先用现有快速检查覆盖直接路径，再按上表补缺口；每项追加检查用一句话说明风险依据。截图只在视觉问题定位、取证或用户要求时选用。

## 三、执行与证据

- 命令标明工作目录与目标范围；手动步骤给出输入、操作与期望；断言指向契约与可观察结果。
- 实际运行时主动查看相关控制台、请求、进程输出，表面正常也检查；发现错误后定位、修复、重演。
- 静态检查、构建、类型检查按改动风险与项目门禁选用，作为对应层证据。

## 四、完成门禁

1. **跑过**：命令或手动步骤实际执行，目标环境/用例正确；测试运行器核对发现数、执行数、失败/跳过与过滤范围。
2. **覆盖**：直接验收项、已知缺陷与风险触发的场景都有结果；零用例或关键跳过保持未验证。
3. **证据**：断言覆盖结果与相关状态/副作用；必要证据缺失时标为未验证/阻塞。

四态结论：**通过**＝已执行且满足预期；**失败**＝已执行且不符预期；**阻塞**＝缺环境/依赖/契约；**未验证**＝场景适用但无有效执行证据。

## 五、失败处理

1. 保存命令、失败断言、输入、环境与相关日志；先用最小失败用例或事件序列定位。
2. 分类处理：本次回归→修复并补回归用例；环境/依赖→修复环境或用同一验收项的替代方法；既有基线失败→用基线复现确认并单列归因；不稳定/时序→固定输入/seed/事件序列定位后重测。
3. 修复后按影响更新范围，重测失败场景与受影响行为；关键项无法解决时报告阻塞与缺口。

## 六、经验回流

漏测缺陷 → 漏掉的风险/场景 → 可复现回归 → 方法更新：通用方法写进本技能对应的 `references/*.md`，项目命令与业务数据留在项目技能，技能描述与 INDEX 按 `auto-skill-creator` 同步。测试产物遵循项目隔离与 `powershell-utf8-safety`。

## 红线兜底

- 以真实风险、场景和独立预期驱动验证；流程走完、退出码为零或用例数量只作参考。
- 受影响验证与项目必要门禁通过后再完成；未执行、零用例或关键跳过保持未验证。
- 失败保留证据、归因、修复和重测；放宽阈值、跳过或只保留重试成功结果都不算通过。
- 既有失败单列披露并附归因；局部验证结论限定在已执行范围。
- 运行验证主动检查相关来源；页面正常、命令成功或空日志只作参考。
- 主观视觉与体验交人工验收；专项由具体风险触发，通过即停止。
