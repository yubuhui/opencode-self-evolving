# 验证计划与结果记录

## 使用方式

在开发计划或任务记录中维护一份验证摘要。小改动可用几行描述；非平凡任务使用下方结构。单个用例的输入、步骤和断言复用 [场景模板](../../test-scenario-design/references/scenario-design.md)。

本文件维护阶段汇总，专项文件维护方法和用例模板，项目维护真实命令与数据。

## 1. 计划模板

```markdown
### 验证范围
- 改动与关联使用方：
- 版本/工作目录/环境/相关依赖：
- 验收依据、关键不变量及待确认项：
- 风险等级与原因：
- 适用专项及重要不适用项的理由：
- 数据准备、隔离、清理与执行预算：

| 验收项/风险 | 场景 ID 与用例位置 | 验证层 | 真实命令或手动入口/步骤 | 成功标准 | 证据位置 |
| --- | --- | --- | --- | --- | --- |
| 具体风险 | 关联场景 | 单元/集成/UI/静态等 | 工作目录＋命令，或可复现操作 | 可观察断言 | 待执行后填写 |
```

把环境依赖和关键假设放在执行前可见的位置。命令来自项目真实入口；手动步骤包含数据、动作及期望。相关高风险场景进入必要验收范围。

## 2. 执行结果模板

```markdown
### 执行结果
- 执行时间、代码版本和环境：
- 运行的命令/手动步骤与实际目标范围：
- 自动化测试：发现/执行/通过/失败/取消/跳过数；关键跳过的场景及原因：
- 静态/文档检查：实际检查目标数、错误/告警及人工判级：
- 手动/UI：具名场景、实际操作、预期对照及证据：
- 失败归因、修复与重测结果：
- 基线既有失败及对比证据：
- 数据/资源清理结果：

| 验收项/场景 | 结论（通过/失败/阻塞/未验证） | 实际结果与证据 | 缺口/剩余风险 |
| --- | --- | --- | --- |

### 总结
- 当前受影响验证与项目必要门禁是否满足：
- 尚未满足的验收项及原因：
- 结论适用范围：
```

计数口径由测试运行器输出决定，说明套件与用例的区别；确实未提供的计数标为未提供，并用可核验的用例报告补证。手动或静态检查使用自己的目标数量，自动化测试计数可标不适用。

## 3. 证据如何判读

| 观察到的情况 | 判读与处理 |
| --- | --- |
| 退出码 0、目标用例实际执行、断言满足 | 对照风险与场景覆盖后，给对应范围通过结论。 |
| 退出码 0、测试运行器发现 0 个用例 | 核对过滤、目录和配置，目标行为保持未验证。 |
| 套件通过但关键场景被跳过 | 关键场景保持未验证，补充实际执行或同等有效验证。 |
| 构建成功、页面 DOM 存在 | 可以说明构建/结构结果；布局、滚动和实际操作仍需 UI 证据。 |
| 静态检查没有错误 | 记录静态检查覆盖；运行行为由对应验证证明。 |
| 文档审计扫描 0 文件 | 先核对是否确实没有适用目标；存在目标改动时修正选择范围。 |
| 环境缺失但逻辑单测通过 | 单测覆盖范围可通过，依赖真实环境的关键项标为阻塞。 |
| 随机探索预算内无失败 | 报告 seed、样本数、输入域与预算，限定该轮探索结论。 |
| 已有失败与当前改动无关 | 附同条件基线证据并单列；本次必要验收与项目门禁仍需满足。 |
| 重试成功但首次失败尚未定位 | 保留失败证据和未解风险，关键场景继续定位。 |

## 4. 记录与复用

- 证据保存到项目约定位置，引用日志、报告、截图或数据查询；说明每份证据支持哪一项断言。
- 缺陷复现保留最小输入/事件序列；通用方法写入对应专项，项目操作留在项目技能。
- 当前必要验证通过后结束。再次执行时，记录触发原因：代码/环境变化、失败或尚未解决的风险。

## 红线兜底

- 计划、执行和结论逐项对应；不得把待执行计划或模拟规则演练表述为实际应用测试通过。
- 证据限定结论范围；不得只列命令名或截图文件名而省略实际结果与所证明的行为。
