# 界面与交互验证

<role>
依据明确的产品/组件契约与实际操作，验证本次改动的客观结果。美观、协调、动效自然度和使用舒适度由人工验收，截图按需辅助定位或取证。范围和停止条件由 [测试总控](../SKILL.md) 负责；项目规范提供组件行为与工具，复杂风险按需引用 [场景设计](test-scenario-design.md)。
</role>

## U1 适用条件与验收依据

在交互发生变化，或存在具体内容、布局、滚动、遮挡与焦点风险时使用。可逆文案、颜色等小改动先针对性核对；具体可达性风险再触发真实界面验证。

1. 读取产品要求、项目 UI/组件规范、现有支持的窗口/设备和操作方式。
2. 确认文本是否允许省略及全文入口、哪层负责滚动、固定元素边界、键盘交互和异步状态。
3. 选出本次实际受影响的契约；例如保存后值一致、全文入口返回完整值、底部按钮可真实点击、关闭后焦点回到约定位置。
4. 关键客观行为有歧义时确认；主观视觉与体验记录为未验证（待人工），给简短入口与关注点。AI 观感建议只作为建议，修改依据来自明确要求或可复现缺陷。

## U2 选择场景

先执行受影响的直接操作或已知问题复现。需要追加时，按具体风险读取 [布局与交互方法](layout-and-interaction.md)；下表为候选场景库：

| 维度 | 代表场景 |
| --- | --- |
| 内容 | 空、短、临界、超长、多行、连续长串、中英文与组合字符、少量/大量条目。 |
| 空间 | 常用窗口、最小支持窗口、断点邻近、低高度、缩放、项目支持的设备。 |
| 状态 | 加载、空、成功、失败、编辑、提交、展开/折叠、动态提示出现。 |
| 操作 | 滚到首尾、点击底部按钮、键盘导航、展开全文、关闭返回、快速切换。 |
| 组合 | 长内容＋窄窗口、错误提示＋低高度、缩放＋固定底栏、加载中切换。 |

只选择与改动或缺陷有关的内容、尺寸、输入方式与状态组合。字数按明确计数规则验证；布局按实际尺寸、点击命中、滚动结果和组件契约验证。

## U3 执行真实渲染与操作验证

1. 使用项目实际浏览器/应用与相关数据，记录可复现入口和必要条件；只有尺寸、缩放、字体影响判断时记录对应参数。
2. 等待目标内容和异步状态进入可观察条件，设超时。
3. 对选中的契约实际滚动、点击、输入或键盘操作，核对结果与必要业务数据。输入方式由受影响契约决定。
4. 发生相关状态变化后，核对受影响的布局、焦点、滚动或输入；真实竞态/存储风险按需转入状态方法。
5. 复用本次运行，按 [运行时信号检查](runtime-diagnostics.md) 主动查看相关来源。仅缺少当前验收必要证据时记录对应缺口。

构建、类型检查及逻辑单测提供对应层证据；真实布局结论以真实渲染和操作为依据。运行环境不可用时记录阻塞，补做可行的静态/组件验证并明确其覆盖范围。

## U4 证据与人工验收

- 以所选契约的操作结果、数据与必要几何测量为主要证据；全文、首尾、焦点等只核对本次受影响项。
- 截图仅在具体视觉问题定位、取证或用户要求时选用，说明所证明的事实。默认交付采用简短操作与断言记录。
- 美观、协调和体验意见交人工确认；已完成的客观检查与未验证（待人工）项目分别明确。设计稿还原可按需截图对照，主观认可仍由人工给出。
- 相关非预期运行错误经修复重演后再判定；必要客观缺口交总控标为阻塞/未验证。
- 所选验证与项目必要门禁通过后结束 AI 验证，主观反馈按用户确认的要求处理。

## 红线兜底

- 所选布局与交互验收以真实渲染和实际操作为证据；不得以构建成功、DOM 存在或单张截图替代可达性验证。
- 文本呈现按契约处理；不得把任意截断都判为缺陷，也不得把所有内容溢出都视为正常。
- 窗口、缩放和状态按风险取样；不要机械要求每个小改动覆盖所有设备与全部组合。
- 弹窗滚动、背景锁定和焦点遵循组件契约；不得强制要求内层滚到底后背景页面继续滚动。
- 页面正常时仍检查本次相关运行信号；不得把截图正常、请求完成或日志为空替代有效检查。
- 截图按需、主观体验交人工；不得默认截图验收，或仅凭 AI 审美判断反复改 UI、宣告视觉验收通过。
