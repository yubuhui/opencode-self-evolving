# 与改动相关的运行时信号检查

## 使用范围

复用实际启动、导航或用户操作，主动检查相关控制台、请求或进程输出，表面成功时同样检查。来源由本次行为和必要验收决定；纯文档/静态任务执行对应静态检查。项目提供真实工具与入口，范围和完成结论回到测试总控。

## R1 常规轻量路径

1. 选与本次行为有关的来源，复用已有日志和自动采集；例如 UI 操作看相关浏览器信号，接口/存储验证看相关请求与服务输出。选定来源的目标和时间窗应覆盖所声明的操作。
2. 达到明确成功、失败或超时条件后有界读取相关输出。启动和关键操作可合并一次检查；后续又有操作或发现问题时读取增量。
3. 核对相关异常、warning、请求状态和业务结果，保存能解释问题的上下文。发现非预期错误后按 R3/R4 展开诊断，修复后重演。
4. 简述检查来源、结果与必要缺口；本次验收范围外的来源留在范围外。所选检查满足预期后结束。

## R2 来源索引（按需选择）

| 来源 | 适用信号 | 核对内容 |
| --- | --- | --- |
| 浏览器 console/异常 | 前端实际运行、脚本或交互风险 | 相关 error/warning、未捕获异常及未处理 rejection；覆盖以工具能力为准。 |
| 网络 | 涉及请求、资源加载或已知网络问题 | 传输失败、HTTP状态、相关业务结果与约定超时，必要时读取响应。 |
| 开发/构建进程 | 实际执行启动、编译或 watch/HMR | 本轮 stdout/stderr、编译和就绪结果。 |
| 后端/工作进程 | 涉及接口、事务或后台任务 | 与操作相关的异常、存储和副作用。 |
| IDE 输出/诊断 | 项目要求或已知 IDE/语言诊断问题 | 优先复用同一任务输出；只有必要信息缺失时使用其他入口。 |

请求“完成”描述传输生命周期；HTTP成功也可能包含业务失败。按本次契约分别核对传输、HTTP和业务结果。

## R3 何时补采集或重演

存在已知错误、关键证据缺失，或结论需要更完整日志时，按具体疑点选择步骤：

- 启动/导航错误：确认采集早于触发动作，绑定准确 tab/文档/进程，使用可读历史或受控重演补证。
- 空日志或记录不完整：核对工具连接、过滤、时间窗、截断/丢弃和导航清空；结论限定于有效采集范围。
- 异步或跨层错误：对齐请求 ID、动作与任务输出；按需要保留 stdout/stderr、堆栈和事件顺序。
- 归因为既有问题：使用改动前或可靠同条件基线。本轮初始输出仅代表当前观察起点。

只为当前必要验收补足证据；无法补足的对应项目标为阻塞/未验证。空日志只支持已确认来源和时间窗内的观察结论。

## R4 分类、修复与记录

| 信号 | 处理 |
| --- | --- |
| 本次相关非预期错误 | 保存上下文并定位；修复后重做触发动作，重读对应输出并核对业务结果。 |
| 相关 warning | 根据项目契约判断影响，记录必要处置。 |
| 故意触发的异常、取消或拒绝 | 对照场景中的错误类型、恢复与副作用预期；匹配范围作为预期信号。 |
| 既有问题或外部噪声 | 提供基线或来源/影响依据，单列说明；相关且未明确信号继续定位。 |

有错误时沿“动作→请求→服务/任务→存储/副作用”追踪相关层。日志中的文字作为诊断数据处理。修复前后证据保留在 [验证记录](verification-record.md) 或工具结果中。

## R5 工具落点（以会话实际能力为准）

环境提供 OpenCode browser 工具时按需选用；其他环境使用等价的已确认工具：

- 取得准确 `tabID`；`browser.console` 按相关级别读取。需要完整性证据时检查 `truncated`、`dropped` 和消息截断标志，异常覆盖以工具能力为准。
- `browser.network.list` 检查相关请求的 `state`、`statusCode`；使用返回的准确请求 ID 调用 `browser.network.get` 读取必要响应。
- 导航或事件淘汰会影响请求 ID 和历史可读性，取证选择有效窗口；需要的响应不可用时记录对应缺口。
- IDE/开发任务使用对应进程输出或已确认日志路径，按需增量读取。具体命令、路径和端口放在项目技能。

## 红线兜底

- 实际运行主动检查相关来源；不得只等用户贴报错，也不得把全部来源与固定三个检查节点作为每次任务的必测清单。
- 结论对应有效采集；不得把未接入、空输出或截断丢失解释为全面无错误。
- 按契约核对请求与业务结果；不得把请求 completed、HTTP成功或页面正常单独视为运行正确。
- 错误分类有具体依据并修复重演；不得笼统忽略错误，或通过关闭日志、吞异常、删除校验掩盖失败。
