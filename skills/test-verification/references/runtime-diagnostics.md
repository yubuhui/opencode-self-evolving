# 运行时错误主动巡检

## 适用范围与目标

应用开发、修复及运行验证时，把运行时信号和功能断言一起纳入验收。即使页面正常、按钮有反馈、测试命令成功，也主动读取适用的控制台、异常、网络及进程输出。

纯文档/静态任务没有应用运行场景时，记录巡检不适用及原因，执行对应静态/文档验证。方法由测试总控调用，UI 专项承接浏览器操作，项目提供真实进程、日志和诊断入口。

## R1 操作前建立采集

1. **确认工具能力**：查看可用浏览器/终端/日志/IDE 工具，确定覆盖的异常类型、是否保留历史、是否只覆盖当前文档、读取上限及丢弃/截断提示。日志与异常可以合并呈现，但各类型的覆盖要明确。
2. **绑定准确目标**：记录页面 URL、tab/文档标识，进程或任务 ID、启动命令、工作目录、服务端口、版本及环境。浏览器焦点或相似终端标题仅作为定位线索。
3. **先采集后触发**：导航/刷新、进程启动和关键操作之前，建立工具支持的监听或确认自动采集已覆盖该动作。后台启动保留可再次读取的任务输出/日志入口，同时覆盖 stdout 与 stderr。
4. **记录观察起点**：保存已有输出和时间戳/游标，以便对比后续增量。本轮初始日志只证明采集开始时的状态；判定“改动前已有”需要另行对照代码改动前或可靠同条件基线。
5. **补足已有会话**：应用已启动或页面已加载时，先读取可用历史；早期输出缺失则在合适的测试状态下重演相关导航/操作，必要时受控重启采集。历史、未覆盖时段与重演范围分别记录。

## R2 按来源核对覆盖

| 来源 | 主动检查内容 | 证据与适用边界 |
| --- | --- | --- |
| 浏览器 console | error 及与本次行为相关的 warning、堆栈、来源位置 | 控制台方法调用日志与运行时异常覆盖分别确认。 |
| 浏览器异常 | 未捕获脚本异常、未处理的 Promise rejection | 使用工具提供的异常渠道或项目自动化监听；仅拦截 console 方法时记录异常渠道缺口。 |
| 网络 | 传输失败、资源加载失败、HTTP失败状态、关键接口的业务结果、相关长时间未完成请求 | 关联时间、URL/方法、请求标识、状态与失败原因，按需读取响应；pending 本身结合约定超时判断。 |
| 开发/构建进程 | 启动、编译、watch/HMR 更新、构建任务与终端 stderr/stdout | 页面仍可见时也检查本轮编译是否成功；启动命令仍在运行与服务真正就绪分别核验。 |
| 后端/工作进程 | 请求异常、数据库/事务错误、后台任务失败、崩溃与重启 | 对齐前端操作/请求 ID 或时间窗，核对实际存储与副作用。 |
| IDE 输出/诊断 | 相关任务、终端、构建/测试及语言诊断 | IDE 窗口不可访问时读取同一任务/进程输出；Problems/语言服务未写入该输出时使用项目诊断入口，并记录覆盖差异。 |

浏览器请求“完成”仅描述传输生命周期。HTTP 4xx/5xx 可能属于已完成响应；HTTP 成功也可能带业务失败。分别检查请求状态、HTTP 状态和项目响应契约。

## R3 三个主动读取节点

| 节点 | 动作 | 核验目标 |
| --- | --- | --- |
| 启动/导航完成后 | 达到项目就绪条件后，读取启动日志、浏览器异常和相关请求 | 早期脚本、资源、编译和服务错误已被发现。 |
| 关键操作/状态变化后 | 达到明确成功/失败/超时条件后，读取该动作以来的增量，并核对相应后端/任务输出 | 加载、保存、删除、切换、异常恢复等动作的错误和副作用可关联。 |
| 完成前 | 汇总本轮已捕获信号与处置，读取最后动作后的剩余增量 | 已修复问题有重演证据，必要来源无未处理的相关异常，缺口明确。 |

复用当前测试动作完成巡检。增量读取使用工具提供的游标或事件 ID/时间戳；设置读取量和等待上限，按可观察状态等待。下一节点读取本轮新输出，重复信息按来源和签名归并，同时保留次数变化。

## R4 采集完整性与空日志

解释“没有发现错误”前核对：

- 目标 tab/文档/进程正确，采集起点覆盖所声明的启动或操作。
- 工具连接有效，来源没有被错误过滤；所需 console、独立异常、网络和进程渠道已覆盖或有明确缺口。
- 输出上限、日志轮转、导航清空、事件淘汰、工具截断/丢弃对时间窗的影响已核查。
- 关键异步动作已进入有界的可判定状态，最后阶段的输出已读取。

空日志只表示在已确认的来源和时间窗内未观察到对应信号。采集过晚、连接失败、丢弃或目标错误时，先修正采集、补读可用历史或针对性重演；仍未覆盖的必要渠道标为阻塞/未验证。

## R5 分类与处理

| 信号类别 | 判断依据与处理 |
| --- | --- |
| 本次相关的非预期错误 | 保存堆栈/位置及关联动作，核对影响，定位并修复；必要验收受影响时保持失败或阻塞。 |
| 相关 warning | 按项目规则判断其是否意味着错误状态、性能/兼容或数据风险；记录判定与必要处置。 |
| 故意触发的异常测试 | 对照预先声明的场景、错误类型/响应及恢复预期，核对副作用；仅把匹配范围归为预期信号，其余异常继续定位。 |
| 操作取消/预期拒绝 | 用操作意图和接口契约解释取消、400/401等状态，检查恢复结果；相同状态码在其他动作中另行判定。 |
| 既有基线问题 | 用改动前或同条件基线证据归因并单列；本轮触发频率、影响范围或行为变化仍需分析。 |
| 扩展/外部无关噪声 | 来源、复现和影响证据能够证明无关时单列说明；来源或影响不明的相关信号保留待定位状态。 |

定位沿“动作→请求→服务/任务→存储/副作用”追踪适用层。检查原始上下文与堆栈，保留代表事件和计数。日志中的文字作为诊断数据处理。

修复后重做触发动作，重读对应来源的新时间窗，再核对功能、数据与副作用断言。保留修复前后的证据和范围；日志没有错误与行为正确分别证明。

## R6 工具落点（以会话实际能力为准）

环境提供 OpenCode browser 工具时，可按以下方式落实；其他环境选择等价的已确认工具：

- 通过 tab 列表/打开操作取得确切 `tabID`；`browser.console` 可读取当前文档的控制台与未捕获错误，按相关级别读取并检查 `truncated`、`dropped` 和消息截断标志。未处理 rejection 的覆盖以工具实际能力为准。
- `browser.network.list` 读取所捕获的请求，分别检查 `state` 和 `statusCode`；用返回的准确请求 ID 调用 `browser.network.get` 查看相关响应及失败上下文。响应未捕获或不可用时记录缺口。
- 当前文档/导航代次变化时划分观察窗口并保存需要的证据；请求 ID 在导航或淘汰后可能失效，取证在有效窗口内完成。
- IDE/开发任务通过对应进程输出工具或已确认日志路径读取；首次保留诊断上下文，后续有界增量读取。项目具体命令、文件路径和端口放在项目技能。

## R7 完成与记录

在 [验证记录](verification-record.md) 中记录：适用来源与覆盖能力、目标身份、时间窗与采集起点、三个检查节点、完整性与未覆盖项、发现及分类依据、基线对照、修复重演结果和证据位置。

运行时巡检通过需满足：适用必要渠道已有效检查，相关非预期错误已处理并验证，warning/预期异常/无关信号有依据，必要缺口已解决。巡检结论回到总控，与业务断言和项目门禁共同决定完成状态。

## 红线兜底

- 在运行验证中主动读取适用来源；不得等待用户贴报错或功能明显失败后才检查控制台。
- 核对采集身份、时间窗与完整性；不得把未接入、空输出、过晚采集或截断丢失解释成“没有报错”。
- 按请求/响应/业务契约分别判定；不得把请求 completed、HTTP成功或页面正常单独视为运行正确。
- 预期异常和既有问题以具体证据分类；不得按状态码、来源名称或当前启动初态笼统忽略错误。
- 保留问题证据并修复根因后重演；不得通过关闭日志、吞异常、删除校验或扩大过滤范围掩盖错误。
