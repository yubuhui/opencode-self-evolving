# 测试场景设计

<role>
在直接路径与已有用例之外，按具体风险推导必要场景，回答「要抓住什么问题、怎样构造、什么才算正确」。范围与停止条件由 [test-verification](../test-verification/SKILL.md) 负责；界面实测由 [ui-test-verification](../ui-test-verification/SKILL.md) 负责；项目技能提供真实命令与契约。
</role>

## 何时使用

- 改动约束、失败处理、状态归属、共享写入等，需要补足明确的覆盖缺口。
- 已知缺陷需要有效复现，已有用例尚未覆盖。
- 发现具体边界、恢复、组合或性能风险，需要选择对应方法。
- 用户要求评估测试充分性、边界、极端操作、模糊或压力场景。

可逆低风险小改动优先复用现有检查，按实际风险做针对性核对。已有充分覆盖时复用用例，新增测试集中于业务行为、回归缺口和高风险组合。

## D1 明确验收依据与不变量

1. 读取需求、项目规范、接口契约、缺陷复现步骤及相关用例；列出功能承诺、约束单位、支持范围和允许的失败行为。
2. 把正确结果写在测试步骤之前。预期优先来自需求、规范样例或独立计算；实现代码用于发现分支与风险。
3. 提取不变量：例如同一逻辑提交产生一次约定副作用、失败后已确认数据保持一致、切换对象后界面归属当前对象。
4. 关键预期有歧义时，列出待确认问题。示例契约与项目已确认契约分别标明；结论依赖的假设须披露。

## D2 按风险选择方法

先说明本次追加验证的目标缺陷，再只读对应方法。下表是路由索引，记录已选择方法及依据即可；未触发方法留在范围外。

| 方法 | 触发信号 | 重点与参考 |
| --- | --- | --- |
| 正常路径/等价类 | 改动分支或输入类别，已有用例有缺口 | 对应代表值及可观察结果，见 [基础设计](references/scenario-design.md)。 |
| 边界 | 改动数量、长度、精度、时间等限制，或已知临界缺陷 | 对相关限制选边界内/上/外，明确计量单位，见基础设计。 |
| 异常与恢复 | 改动依赖访问、校验、写入或恢复逻辑，影响失败一致性 | 在相关失败点验证反馈、数据和恢复，见基础设计。 |
| 状态与时序 | 改动状态转换、请求归属，或存在乱序缺陷 | 相关转换与事件顺序，见 [状态与一致性](references/state-consistency.md)。 |
| 重复/并发 | 共享写入、重试副作用或真实冲突风险 | 按契约核对副作用次数、冲突处理及最终数据，见状态与一致性。 |
| 输入扰动/模糊 | 解析/导入改动，或明确的复杂输入探索目标 | 先相关畸形样本；随机探索另定 seed 和预算，见 [模糊与压力](references/fuzz-and-stress.md)。 |
| 容量/压力 | 性能敏感改动、已知容量缺陷或明确性能要求 | 目标工作量、阈值与资源预算，见模糊与压力。 |
| 布局/交互 | 改变交互，或具体内容/布局/可达性风险 | 受影响的真实操作与客观契约，转入 UI 专项。 |

“暴力测试”作为需求描述时，先明确是畸形输入、随机操作、重复并发，还是资源压力，再选对应方法。前后端都按功能风险选方法。

## D3 推导最小充分场景集

1. 先复用或补一个能证明改动行为的直接场景，再从具体风险追加必要用例。
2. 从适用参考方法推导场景；每个场景明确目标缺陷，合并验证目标相同的重复用例。
3. 对容易相互影响的维度显式组合，如「小窗口＋错误提示」「保存中＋切换对象」「提交成功但响应丢失＋重试」。
4. 已选维度组合较多时用风险排序与成对覆盖缩减；已知耦合单独验证。只记录验收范围内的抽样边界与必要缺口。
5. 缺陷修复优先建立失败复现：用修复前版本或受控复现证明用例能抓到问题，再验证修复结果；无法重现时如实记录证据限制。

## D4 落实验证层与测试质量

- 纯计算/规则用单元层；真实模块、序列化、事务或接口协作用集成层；用户完整操作和布局用浏览器/端到端层。以能抓住目标缺陷的最低充分层为主，跨层风险补对应集成证据。
- 断言用户或调用方可观察的结果、契约和副作用。共享正确性依据来自需求或独立样例；测试中的期望值与被测算法保持独立。
- 测试数据使用隔离账户、临时目录/数据库或唯一标识；注明初态、时钟/时区、seed、依赖版本等相关条件，执行后清理并验证可重复运行。
- Mock 放在当前测试边界之外的依赖，用于控制失败和时序；边界协议、持久化、真实布局等风险保留对应真实集成验证。
- 异步验证等待可观察条件并设超时；并发次序通过可控屏障/延迟建立，失败保留事件顺序。

## D5 输出与交接

默认简述「风险→场景→预期→方法」，执行后补结果。复杂时序、数据准备或故障注入场景再选用 [扩展场景模板](references/scenario-design.md) 的相关字段。

设计完成的标准：适用高风险均有具名场景，预期可判定，执行入口真实可用或明确标为阻塞。场景设计完成与应用验证完成分别记录，执行与最终门禁回到总控。

## 红线兜底

- 预期依据需求、契约与独立样例；不得复制被测实现来计算期望值或以「没有崩溃」代替正确性断言。
- 方法按适用风险展开；不得按前后端或错误可见性排除某类测试，也不得把所有专项机械用于每个小改动。
- 缺陷与高风险行为优先建立有效回归；不要为低风险可逆改动或实现细节机械补测试。
- 专项按具体风险读取与执行；不得要求每次逐项分析整张方法表或填写全部不适用理由。
- 场景设计、实际执行、证据结论分别记录；未执行或关键预期未明确时，不得声称对应行为验证通过。
