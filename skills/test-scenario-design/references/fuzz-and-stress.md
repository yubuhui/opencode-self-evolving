# 输入扰动、模糊测试与容量压力

## 适用条件与方法选择

先把“暴力测试”需求转成明确目标：

| 目标 | 方法 | 关注的失败 |
| --- | --- | --- |
| 解析/导入异常数据 | 结构化畸形样本、模糊测试 | 错误接纳、异常逃逸、错误结果、资源失控。 |
| 用户乱序/高频操作 | 有界随机操作序列，配合状态方法 | 状态卡死、过期结果、重复副作用。 |
| 容量和速度 | 负载、容量、压力或持续运行验证 | 延迟超标、错误增长、资源泄漏、无法恢复。 |

结构化边界和已知失败样本优先；随机测试用于扩大探索范围。方法可以组合，但分别记录输入模型、正确性依据与预算。用例记录复用 [场景模板](scenario-design.md)，并发语义见 [状态与一致性](state-consistency.md)。

## A. 输入扰动与模糊测试

### A1 定目标与预期

明确被测入口、允许的输入类型、格式契约和副作用。按输入类别断言：

- 合法输入：结果符合独立样例、参考实现或业务不变量。
- 非法输入：按约定拒绝/容错，错误可识别，持久化和资源状态正确。
- 部分接纳：成功与失败项目可核对，重试语义明确。

可用性质包括序列化往返、集合守恒、顺序无关、幂等或变换关系，但先确认该性质确实属于目标契约。例如有精度损失的转换，应使用约定容差。

### A2 建种子语料与生成策略

1. 收集最小合法样本、典型真实结构、边界样本与缺陷样本，使用合成或脱敏测试数据。
2. 每次先扰动一个相关维度，再增加高风险组合：

| 维度 | 候选扰动 |
| --- | --- |
| 结构 | 缺字段、重复字段、类型错配、顺序变化、闭合缺失、深层嵌套。 |
| 内容 | 空白、控制字符、分隔符、不同换行、混合语言、按格式构造的异常转义。 |
| 编码 | BOM、截断字节、非法字节序列、组合字符、边界计数差异。 |
| 规模 | 长行、大集合、深结构、接近容量限制及越界值。 |
| 操作序列 | 加载/切换/提交/取消/重试的交错，遵循明示的状态模型。 |

3. 使用固定 seed，记录生成器版本、用例序号、长度/深度/数量上限、最大次数和总时长。
4. 选择结构感知生成以深入目标分支，并保留一组完全无效输入验证入口拒绝行为。

### A3 执行与失败复现

- 每例使用明确初态，设单例超时、总时长和资源预算；可能失控的输入在可终止的隔离进程/环境运行。
- 每轮同时检查返回值/错误、不变量、副作用和资源释放，记录实际执行与拒绝数量。
- 发现失败时保存 seed、生成器版本、准确输入/操作序列、环境、日志、实际与预期。seed 之外保存原始失败样本，保证生成器变化后仍能复现。
- 缩减输入或步骤并保留同类失败判据，直到得到便于理解的最小样本；转成固定回归用例。
- 修复后先重放最小样本与相关语料，再按原预算验证受影响探索范围。

### A4 完成与证据

报告实际样本数、预算、seed、语料覆盖维度、失败/超时数、最小样本位置及未覆盖输入域。预算内未发现问题表示该次探索通过，结论限定于记录的范围。

## B. 容量、压力与持续运行

### B1 先定契约、环境与阈值

由产品目标或明确的基线比较制定标准。记录机器/运行时/数据库、版本、测试数据、缓存冷热、外部依赖及采样方式。

分别确定：

- 工作量：数据集规模、单请求大小、请求到达率、并发数、持续时间。
- 指标：完成吞吐、延迟分位数、错误率、资源峰值、队列长度、恢复时间。
- 判定：在规定工作量下的阈值、允许降级和恢复要求。

缺少阈值时，先做有界测量并报告观察值与待确认目标，性能是否达标保持未判定。

### B2 选择负载模型

| 模型 | 推导方式 | 核验重点 |
| --- | --- | --- |
| 正常负载 | 有代表性的读写比例与数据分布 | 基准正确性、延迟和吞吐。 |
| 容量边界 | 目标规模内/目标点/略超目标 | 分页、内存、响应及限额反馈。 |
| 递增压力 | 按固定阶梯提高到达率或并发数 | 饱和点、排队、错误、约定降级。 |
| 突发/恢复 | 有界突发后恢复正常工作量 | 积压能清空，状态和资源恢复。 |
| 持续运行 | 按泄漏或长期退化风险确定时长 | 资源趋势、句柄/连接释放、长期正确性。 |

逐项改变主要维度以便归因；真实耦合场景另作组合。并发数与到达率分开记录，观察发起量和完成量，避免只因客户端发送变慢而误判服务承载能力。

### B3 执行与停止

在隔离测试环境设置最大规模、总时长、资源上限和异常停止条件；运行前声明达到哪条条件即停止并保留证据。

按目标需要预热，标注预热样本；在稳态区间采样并保存原始指标。运行中同时核对结果与副作用，运行后验证数据、队列、连接及用户操作恢复。

同条件比较基线与改动版本。出现波动时检查环境和样本量，按具体疑点复测并保留完整结果；重大正确性失败先定位再继续加压。

### B4 完成与证据

报告环境、负载模型、阈值来源、实际发送/完成量、延迟分布、错误、资源峰值与恢复结果。实际未达到目标负载、样本不足或测量受依赖故障干扰时，标为未验证或阻塞，并说明已有观察值。

## 红线兜底

- 固定 seed、输入/操作样本、预算和失败判据；不得把不可复现的随机失败简单归为偶发通过。
- 正确性、资源和恢复共同验收；不得只以进程未崩溃或平均耗时达标判定全部通过。
- 负载在隔离环境按预算执行；不得默认对生产环境或共享第三方服务无界加压。
- 性能结论对应真实阈值和实际工作量；不得自创通用性能门槛或把未达目标负载的结果算作达标。
