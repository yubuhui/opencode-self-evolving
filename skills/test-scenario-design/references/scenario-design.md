# 基础场景设计：等价类、边界、异常与组合

## 适用条件与风险

总控选择相关风险后按需读取对应章节。针对本次改动的分支、约束或失败点推导场景；下方样本用于选取，范围由具体目标缺陷决定。

本文件维护统一用例模板；状态时序见 [状态与一致性](state-consistency.md)，随机输入和规模验证见 [模糊与压力](fuzz-and-stress.md)。

## 1. 建立正确性依据

记录需求/契约或用户确认的预期、适用版本、关键不变量。常见不变量包括总量守恒、唯一性、引用有效、权限范围正确、操作后界面与存储一致。

先确定正常成功、可预期拒绝、系统故障各自应该产生的结果：返回值、错误类型、数据变化、提示与恢复入口。需求缺口用待确认项标明；候选行为可用于探索，正式验收以确认后的契约为准。

## 2. 等价类：找行为不同的输入组

1. 按业务规则划分类别，例如合法/非法、存在/缺失、允许/受限、单项/批量、不同文件格式。
2. 在每类选择能代表该行为的值，给出期望结果；同类中已知存在不同处理路径时继续拆分。
3. 对字段分别考虑：缺字段、null、空串、空白串、0、false、空集合、错误类型。是否等价由契约决定。
4. 对集合选择空、一个、多个，以及重复项、排序变化、首尾项；检查返回值和副作用。

示例契约：搜索条件为空表示全部，而缺少租户标识属于请求错误。两者的“空”含义不同，需要不同断言。

## 3. 边界：从限制推导邻近取值

### 推导步骤

1. 列出限制及其来源：数值区间、字符数/字节数、批量数量、页数、有效期、精度、路径长度、最大文件大小等。
2. 明确边界包含关系、单位、离散步长或浮点容差、时区与计时起点。
3. 对每条相关边界选内侧、边界本身、外侧取值；离散整数常用 min−1/min/min+1 与 max−1/max/max+1。数值受定义域限制时选最接近的合法构造方式。
4. 按受影响约束补相关空/零/单项；极端规模在容量风险下展开。使用等价类避免重复，连续尺寸、时间和精度按领域最小有意义差值取样。
5. 对接受和拒绝分别断言：合法值保存/返回正确；非法值给出约定反馈且保持约定数据状态。

### 示例契约与用例

| 示例契约 | 推导输入 | 正确结果 |
| --- | --- | --- |
| 密码允许 8～16 个约定计数单位 | 7/8/9、15/16/17 | 两端包含，越界拒绝，错误信息匹配约束。 |
| 每页最多 20 条 | 总数 0/1/19/20/21，最后一页 | 总数、页码、首尾记录及下一页状态正确。 |
| 到期时刻起失效 | 到期前/恰好到期/到期后 | 按约定时钟和时区判断；响应与持久化状态一致。 |
| 上传上限为 N 字节 | N−1/N/N+1 字节及空文件 | 按契约接纳/拒绝，失败后无残留业务记录。 |

字符数、Unicode 码点、用户感知字符、编码字节数及显示宽度分别确定。视觉容器容量使用真实渲染验证，参考 UI 专项。

## 4. 异常与恢复：沿操作链找失败点

先画出「校验→请求/读取→处理→持久化→返回→界面更新」，在涉及本次改动的边界注入可控故障。

| 失败点 | 构造方法 | 预期应包含 |
| --- | --- | --- |
| 输入/文件校验 | 类型错误、格式损坏、必需信息缺失 | 清晰反馈，副作用符合拒绝契约。 |
| 依赖访问 | 超时、断开、指定失败响应、权限变化 | 错误状态明确，加载状态结束或进入约定重试状态。 |
| 中途处理/落盘 | 在已执行部分步骤后注入失败 | 原子回滚，或明确的部分成功清单与可继续位置。 |
| 已提交但响应丢失 | 提交成功后丢弃响应，再重试 | 按幂等/冲突契约确认结果，数据和副作用一致。 |
| 恢复操作 | 纠正输入、恢复依赖、重试/取消 | 能继续操作，已确认数据和用户可恢复输入得到保留。 |

对选中的异常场景核对受影响的反馈、数据一致性与恢复要求；控件、资源、重试按相关契约选用。

故障注入限定于可控测试环境，明确注入点、持续时间与清理动作。若只能模拟接口，注明尚未验证的真实依赖行为。

## 5. 状态与组合选择

- 找出会改变规则的状态：加载、空、成功、错误、编辑中、提交中、关闭、切换对象等，交给状态参考方法展开。
- 优先交叉会争用同一资源或布局的因素：错误提示×小窗口、超长文本×固定宽度、重复提交×响应超时。
- 组合过多时按影响、发生可能和已有缺陷选代表；成对覆盖降低组合量，高风险多因素耦合单独列出。
- 覆盖率指标辅助发现遗漏；是否充分以关键风险和行为断言为依据。

## 6. 统一场景模板

默认几行说明风险、预期、操作和结果。复杂时序、故障注入或数据准备场景按需从下表选字段，记录仅覆盖本次验收范围。

```markdown
### T-编号：场景名称
- 风险/验收项：要发现的具体问题与优先级
- 预期依据：需求、契约、缺陷复现或已确认假设
- 前置状态与数据：环境、初态、隔离方式、相关时区/时钟/seed
- 输入与操作：可复现步骤，含必要时序或故障注入点
- 预期结果：可观察输出、状态、持久化和副作用断言
- 验证方法：真实命令或手动步骤，关联用例/文件/界面
- 实际结果与证据：执行数、断言结果、日志/截图/数据查询等
- 结论：通过 / 失败 / 阻塞 / 未验证
- 清理与剩余风险：数据/资源恢复，未覆盖项及原因
```

## 7. 用例有效性与完成标准

- 每项高风险有明确场景，输入能触达目标分支，断言覆盖行为和相关副作用。
- 优先断言输出、存储状态与外部可见行为。Mock 调用次数仅在调用次数本身属于契约时作为核心证据。
- 缺陷用例优先证明修复前失败、修复后通过；缺少修复前环境时记录可靠复现材料和证据限制。
- 独立运行与必要的组合运行结果一致；通过唯一测试数据、可控时钟和资源清理保证隔离。
- 记录实际测试数、失败/跳过、环境和证据。设计覆盖与执行覆盖分别汇总，未执行的关键用例保持未验证状态。

## 红线兜底

- 先定验收来源与预期再选输入；不得以被测代码的现有输出直接充当正确答案。
- 边界按单位与包含关系推导；不得把所有边界机械简化为整数加减一。
- 用例断言行为与副作用；不得只验证函数被调用、页面能打开或操作没有抛异常。
