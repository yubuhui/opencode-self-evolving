# 状态、时序与数据一致性验证

## 适用条件与风险

适用于加载/编辑/保存/取消/切换、后台任务、共享记录、多窗口、重试、导入和批处理。重点发现非法转换、过期响应覆盖、重复副作用、丢失更新、部分提交及恢复失败。

用例字段复用 [统一场景模板](scenario-design.md)。验收以产品状态机、接口、事务与幂等契约为准；以下情景须先确定项目采用的语义。

## 1. 建立状态与转换表

1. 列出可观察状态和关联数据：当前对象、请求标识、表单内容、保存版本、按钮状态、错误/成功提示。
2. 列出事件：用户操作、响应返回、超时、取消、路由切换、订阅推送和重启。
3. 为相关转换写出前态、事件、允许性、后态与副作用。选出本次改动涉及的合法、重复及不允许的转换。

示例契约：同一逻辑保存幂等；关闭页面后可以继续完成服务端事务，界面只接受当前对象的结果。

| 前态 | 事件 | 预期后态/结果 |
| --- | --- | --- |
| 空闲 | 加载 A | 显示加载状态，记录目标 A。 |
| 加载 A | 切换 B | 当前目标为 B，A 的结果按过期响应策略处理。 |
| 编辑中 | 提交 | 进入提交中，同一逻辑提交的标识稳定。 |
| 提交中 | 再次提交 | 依契约禁用、合并或幂等接纳，副作用次数正确。 |
| 提交中 | 失败 | 可继续编辑/重试，数据和输入按恢复契约保留。 |
| 提交中 | 关闭 | UI 结束交互，事务结果和返回界面的展示可核对。 |

## 2. 从单步扩展到序列

- 正常顺序：进入→加载→编辑→保存→重新读取，核对界面与存储。
- 中途打断：加载中关闭、保存中切换、批量处理中取消、删除当前选中项。
- 重复操作：双击、连续快捷键、同一请求重发、断线后的重试。
- 反向操作：失败后重试、撤销后重做、关闭后重新打开。
- 多对象交错：A→B→A 快速切换，不同对象响应交错。

为关键序列标明每一步预期状态，结束后检查持久化结果。序列选择基于真实风险，重复次数与时长设定有界预算。

## 3. 请求乱序：控制到达顺序

1. 发起 A，暂缓其响应；切换 B 并发起 B。
2. 先完成 B，再释放 A；检查当前视图、错误提示、加载标志和缓存各自所属对象。
3. 对关键分支再测 A 失败/B 成功、A 成功/B 失败，以及取消后响应到达。
4. 用可控响应队列、屏障或测试替身构造顺序；实际协议风险在集成层验证。

示例预期：当前对象为 B 时，A 响应只能按缓存策略更新 A，界面数据与加载状态仍属于 B。其他项目以其请求归属契约为准。

等待条件应能观察到目标状态并有超时上限。记录请求 ID、对象 ID、发送/响应/应用结果的顺序，供失败复现。

## 4. 重复提交与重试

1. 明确幂等边界：哪个操作标识代表同一逻辑动作、有效期多长、不同内容复用标识如何处理。
2. 构造连点/同时发送、请求超时重发、提交成功但响应丢失、刷新后重试。
3. 核对响应、记录数量、通知/扣减等副作用次数，以及重新查询结果。
4. 同时验证用户确实要执行的第二次独立操作；使用不同操作标识，按契约允许新的副作用。

单纯界面按钮禁用只能证明一个入口的交互防护；需要服务端幂等时在接口/存储边界验证重复请求。

## 5. 并发冲突与持久化

- 两个独立客户端读取同一版本，再交错修改；根据版本冲突、合并或覆盖策略核对结果。
- 修改与删除同时发生、批处理与单项编辑相遇、读取发生在提交前后；检查引用、列表、详情与总数是否一致。
- 事务提交与中断：按项目承诺验证原子回滚或部分成功清单；重新读取/重启后的状态仍符合契约。
- 对余额/计数/配额等约束验证不变量，例如总量守恒、允许范围、唯一性；直接查询持久化结果辅助核对。

并发验证使用隔离环境、独立连接/客户端和可控起跑屏障。若目标风险是数据库锁、事务或真实协议，选对应集成环境。

## 6. 恢复与清理

对每个中断点检查：处理中状态能否结束、用户输入能否恢复、部分结果能否识别、重试能否继续、临时资源是否清理。后台任务按契约验证取消、继续执行或下次恢复。

测试结束恢复网络/替身/时钟配置，清理临时记录和连接。需要重启验证时记录重启前后的状态与数据快照。

## 7. 完成与证据

- 相关转换、关键交错及失败恢复都有可判定场景与实际结果。
- 保存转换表、事件顺序、操作标识、响应、最终存储查询和副作用计数；记录契约与执行环境。
- 时序失败保存能稳定复现的最小事件序列。随机发现的序列固定后加入针对性回归。
- 只在 UI/Mock 层执行的场景明确其覆盖边界，事务/真实并发仍需对应证据；缺环境时交总控标记阻塞或未验证。

## 红线兜底

- 并发断言来自明确冲突/幂等契约；不得把「任何重复操作都只执行一次」当作通用业务规则。
- 核对最终持久化与副作用；不得只根据成功提示或按钮禁用判定一致性。
- 时序通过屏障、可控响应和有界条件等待建立；不要依赖任意固定等待来掩盖竞态。
