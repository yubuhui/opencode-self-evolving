# 界面与交互验证

<role>
从真实渲染和实际操作验证内容是否可读、关键操作是否可达、交互结果是否正确。通用场景设计引用 [test-scenario-design](../test-scenario-design/SKILL.md)，范围和完成门禁由 [test-verification](../test-verification/SKILL.md) 负责；项目规范提供支持尺寸、组件行为和实际工具。
</role>

## U1 适用条件与验收依据

适用于页面、弹窗、侧栏、列表、表单、文本容器及影响其内容或状态的改动。

1. 读取产品要求、项目 UI/组件规范、现有支持的窗口/设备和操作方式。
2. 确认文本是否允许省略及全文入口、哪层负责滚动、固定元素边界、键盘交互和异步状态。
3. 识别本次布局与操作风险：内容增多、可用空间减小、状态增高、元素遮挡、焦点和滚动丢失等。
4. 关键行为未约定时记录待确认项；探索结果与正式验收结论分别记录。

## U2 选择场景

按风险读取 [布局与交互方法](references/layout-and-interaction.md)，从以下维度选适用项：

| 维度 | 代表场景 |
| --- | --- |
| 内容 | 空、短、临界、超长、多行、连续长串、中英文与组合字符、少量/大量条目。 |
| 空间 | 常用窗口、最小支持窗口、断点邻近、低高度、缩放、项目支持的设备。 |
| 状态 | 加载、空、成功、失败、编辑、提交、展开/折叠、动态提示出现。 |
| 操作 | 滚到首尾、点击底部按钮、键盘导航、展开全文、关闭返回、快速切换。 |
| 组合 | 长内容＋窄窗口、错误提示＋低高度、缩放＋固定底栏、加载中切换。 |

字数限制使用明确的计数规则；视觉容量使用字体、尺寸和实际渲染判断。场景选择服务于本次风险，可逆小改动复用现有验证。

## U3 执行真实渲染与操作验证

1. 使用项目实际浏览器/应用环境和有代表性的数据，记录路由、版本、窗口尺寸、缩放与关键字体条件。
   按 [运行时错误巡检](../test-verification/references/runtime-diagnostics.md) 在导航/刷新及关键动作前确认 console、未捕获异常/未处理 rejection 和网络的采集覆盖，绑定准确 tab/文档与时间窗；关联开发和后端输出。
2. 等待目标内容、字体和异步状态进入可观察条件，并设超时；动效按项目测试约定稳定采样。
3. 检查全文入口、溢出、容器和固定元素；实际滚动到目标内容，检查点击命中与遮挡。
4. 用项目支持的鼠标/触摸及键盘方式完成关键操作，核对操作后界面和必要的业务数据。
5. 状态切换后再核对布局、焦点、滚动和输入；跨请求或存储风险转入场景设计的状态方法。
6. 启动/导航完成后、关键操作后及收尾主动读取上述来源的增量，即使界面表面正常。分别核对传输失败、HTTP状态与业务错误；采集缺口、预期异常和基线归因按共用巡检方法处理。

构建、类型检查及逻辑单测提供对应层证据；真实布局结论以真实渲染和操作为依据。运行环境不可用时记录阻塞，补做可行的静态/组件验证并明确其覆盖范围。

## U4 完成与证据

- 按约定完整阅读内容，或通过可发现、可操作的全文路径取得内容。
- 首尾和关键操作可达，遮挡/滚动/焦点行为符合组件语义与产品契约。
- 动态状态、失败提示和关键操作后的数据结果正确，相关高风险组合已验证。
- 保存代表场景截图、实际操作与断言结果、必要的几何信息、异常日志和剩余缺口；截图与功能证据相互补充。
- 主动巡检有来源、时间窗、完整性与分类处置记录；相关非预期运行错误经修复重演和对应来源复读验证，必要渠道缺失如实保留未验证项。
- 结论回到总控：记录通过、失败、阻塞、未验证项及依据。

## 红线兜底

- 验证真实渲染、滚动和操作结果；不得以构建成功、DOM 存在或单张截图替代布局与可达性验证。
- 文本呈现按契约处理；不得把任意截断都判为缺陷，也不得把所有内容溢出都视为正常。
- 窗口、缩放和状态按风险取样；不要机械要求每个小改动覆盖所有设备与全部组合。
- 弹窗滚动、背景锁定和焦点遵循组件契约；不得强制要求内层滚到底后背景页面继续滚动。
- 页面正常时仍主动读取控制台、异常与网络；不得把截图正常、请求完成或日志为空替代有效运行时检查。
