# 计划子代理 + 复核门禁

<role>
适用于所有 opencode 项目的规划阶段纪律：planner/reviewer 分离（四眼原则）。
1. 大型/涉规范任务先由子代理产出《开发计划》并落盘。
2. 主进程按硬清单复核，通过后才进入执行；不通过退回子代理重出（上限 2 轮）。
3. 计划文件是执行、复核、中途更新的唯一事实来源。
</role>

## 触发门槛（不满足则豁免，不增加开销）

满足任一进入规划流程：
- 命中 `phased-refactor-and-report` 的大型改造判定（3+ 文件 / 2+ 模块 / 核心共享代码 / 2+ 逻辑变更点 / 高风险）
- 改动涉及红线 / 开发规范 / 技能体系（AGENTS.md、AI-开发规范.md、SKILL.md、INDEX.md）
- 用户明确要求"先出计划"

## 流程

```
P1 子代理出计划 → P2 主进程复核 →（不通过→退回P1，上限2轮）→ 通过 → P3 执行
```

### P1 子代理出计划（planner）

1. 主进程把「任务描述 + 相关规范（AGENTS.md / 项目 AI-开发规范.md / 相关 SKILL.md）+ 现状分析」交给 `general` 子代理。
2. 子代理产出《开发计划》，主进程用 Write 落盘 `opencode/plans/{slug}-{yyyyMMdd}.md`，固定模板：

```markdown
# {任务} 开发计划
## 一、目标与范围（做什么/不做什么）
## 二、阶段拆分（每阶段：目标 | 涉及文件 | 验收项/风险与场景 | 验证命令或手动步骤/成功标准/证据 | 回滚方案）
## 三、风险与依赖
## 四、技能同步预案（触及 页面/模块/命令/架构/红线 时的技能更新安排）
```

### P2 主进程复核（reviewer，硬清单逐项核查）

A. 计划制定规范（承接 `phased-refactor-and-report`）：
- [ ] 每阶段可独立测试 / 独立提交 / 独立回滚
- [ ] 每阶段只做一类变更（先结构后行为、先加后删）
- [ ] 阶段粒度合理（理想 1 阶段 1 commit）
- [ ] 每阶段写明目标 / 涉及文件 / 验收项与相关风险场景 / 验证命令或可复现手动步骤 / 成功标准与证据（按 `test-verification` P2 设计）
- [ ] 测试投入与风险相称：重要边界、异常、状态/交互有适用性分析，环境依赖与关键未验证项可见（方法由测试总控按需调用专项）
- [ ] 含应用运行场景时，已安排日志/异常/网络与相关进程的前置采集、启动后/关键操作后/收尾主动读取及覆盖缺口记录（见 `test-verification` 运行时巡检）
- [ ] 有风险点与回滚方案

B. 开发规范（承接 `quality-baseline`；涉前端项目另加载项目前端规范）：
- [ ] 代码结构：复用非复制、单一来源
- [ ] 维护性：易测易回滚、抽象适度
- [ ] 界面统一 / 操作一致 / 动效合适（涉前端时）
- [ ] 涉规则改动时：白熊三原则（禁令配正面替代、行为与诊断分离、正面先行）

C. 一致性：
- [ ] 与任务目标对齐，无遗漏、无越界
- [ ] 阶段顺序依赖正确（前置在前）
- [ ] 技能同步预案已包含

复核输出固定格式：`逐项 通过/不通过+理由 → 结论(通过/退回/小瑕疵) → 修改意见`。

### P3 闭环（复核结论三态）

- **通过** → 进执行，计划文件即执行依据。
- **小瑕疵**（漏验证命令、措辞不清等）→ 主进程直接修文件并标注，视为通过。
- **不通过**（结构性问题：阶段不可独立回滚、目标遗漏、违反红线）→ 附修改意见退回 P1，上限 2 轮；超限上报用户裁决，由用户拍板后再开工。

### P4 执行

回归 `phased-refactor-and-report`：每阶段 `实现→测试→提交`；中途计划外事项 → 暂停 → 更新计划文件 → 变更较大时重新走复核。

## 关键命令 / 模式

- 出计划：`task` 工具（`subagent_type: general`），prompt = 任务 + 规范清单 + 输出模板 + 落盘路径。
- 落盘：Write 工具（计划含中文，遵循 `powershell-utf8-safety`）。
- 复核：对照清单逐项给出 通过/不通过 + 可核验依据，结论三态明确。

## 注意事项（红线）

- 禁止橡皮图章：每项必须给出可核验依据，不写"OK"了事。
- 迭代上限 2 轮是硬约束，防死循环；超限上报用户裁决。
- 不追求完全独立复核：复核者与规划者共享上下文，独立性有限，硬清单保证下限；真正独立留给用户终裁。
- 计划文件是唯一事实来源：执行、复核、中途更新都围绕它，禁止口头计划漂移。
- 规划前置：大型改造先出计划并复核通过，经用户确认后才动手（用户明确指示直接做除外）。
