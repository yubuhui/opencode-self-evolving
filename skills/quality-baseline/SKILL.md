# 通用开发质量底线

<role>
适用于所有 opencode 项目的默认开发纪律，日常开发全量生效。
五项原则互相约束，不得为单一项牺牲另一项。
</role>

## 五项原则与适用场合

| 原则 | 主要适用场合 | 自查要点 |
| ---- | ------------ | -------- |
| 代码结构清晰 | 一切代码，尤其共享/复用模块、新增页面与库文件、大型改造 | 单一来源不复制；分层职责；命名清晰 |
| 开发维护方便 | 同上，兼顾后续维护者 | 易理解、易测试、易回滚；避免过度抽象 |
| 界面外观统一 | 前端页面/组件/JS 生成 DOM | 颜色间距用 CSS 变量；组件走共享样式；弹窗/表单/按钮用统一组件 |
| 操作逻辑一致 | 交互逻辑：弹窗、确认/删除、表单校验、折叠展开 | 同一语义同一操作方式；统一入口函数 |
| 动画效果合适 | 涉及动效的开发：loading、展开收起、过渡 | 跟随系统规范；不喧宾夺主；不用 emoji 充当图标 |

## 使用纪律

1. **默认全量适用**：任何代码改动都要符合五项，只是侧重点不同。
2. **按任务类型自查**：
   - 纯前端 UI 改动 → 重点看「界面外观 / 操作逻辑 / 动画效果」。
   - 共享库与重构 → 重点看「代码结构 / 开发维护」。
   - 大型改造 → 全部五项 + 分阶段规范（`phased-refactor-and-report`）。
3. **互相约束，禁止为单一项牺牲另一项**：
   - 为界面统一复制组件代码 → 违反结构清晰（应提炼共享模块复用）。
   - 为代码结构过度抽象 → 损害开发维护方便。
   - 动画炫技（内联 style、自造动效）→ 违反统一与规范。
4. **项目级规范优先**：项目 AGENTS.md 的具体规范（前端样式规范、共享组件清单、Loading 规范等）更具体，冲突时以项目规范为准；项目无对应规范时才退回本通用底线。

## 关键检查模式（改动完成后自查）

- 新 UI 是否复用项目共享组件/变量，而非复制内联样式？
- 新交互是否与项目已有交互方式一致（弹窗/确认/表单）？
- 新模块是否放共享库目录，而非页面内重复实现？
- 动效是否跟随项目动画规范，而非临时内联？
- 是否为了美观/炫技引入了影响可维护性的复杂度？

## 注意事项（红线）

- 禁止为「好看」自造与项目风格不一致的组件/动画。
- 禁止为「结构」而过度设计，导致简单功能复杂化。
- 禁止在页面内重复实现已存在于共享库/共享样式的功能。
